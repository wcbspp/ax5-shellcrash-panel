## 当前部署

当前使用 ShellCrash 适配源的 ARMv7 mihomo v1.19.28，另已验证 sing-box mini 1.12.13。已安装 ShellCrash 1.9.4release 原工具，`crash` 是实际可执行入口；菜单启停、内核切换与网页共用 procd 服务。AX5 适配层负责保存内核包、生成运行配置和回退。其他原生高级菜单尚未逐项验证，订阅、DNS、分流及监控以本项目网页设置为准。

## 分流与内存

Mix 模式：国内域名和例外返回真实地址，其他 A 查询返回 Fake IP；流量仍按同一规则分流。大陆 IP、局域网直连，其他 TCP 代理。普通 UDP 直连，Fake IP 的转发 UDP 拒绝以便应用回落 TCP。IPv6 DNS 查询当前拒绝，不提供完整 IPv6 代理。

AX5 目前是中继设备，未改网络 DHCP。其他客户端若要经过 AX5，须按网络拓扑设置网关和 DNS 为 192.168.31.1；仅安装面板不会自动接管整个局域网。

默认提醒 20 MB、保护 14 MB、自动清理 20 MB。保护指低内存时暂缓更新配置，不是停止代理。自动清理只删除本适配器的临时校验文件并裁剪日志，不删除配置、运行内核或 Fake IP 数据，也不执行全局 drop_caches。清理阈值填 0 关闭自动清理；日志大小仍每分钟检查，超过 64 KB 裁剪到末尾 32 KB。Go 的 GOMEMLIMIT=12MiB 并非进程 RSS 上限。

## ZeroTier 修复与剩余问题

原 Entware ZeroTier 版本 1.14.1-2a。前台启动捕获退出码 139，并生成信号 11 的 core 文件，确认是段错误。关闭自动端口映射后能上线；故障与该路径相关，但未获得符号化调用栈，不能精确断言是哪一个库函数。现有 libminiupnpc 为 2.2.8；OpenWrt 上游有同版本库兼容修复记录：[上游修复](https://github.com/openwrt/packages/pull/26088)。

新增 `/opt/var/lib/zerotier-one/local.conf`：

```json
{"settings":{"portMappingEnabled":false}}
```

这只关闭 ZeroTier 自身 UPnP/NAT-PMP 自动映射，仍保留 UDP 打洞与 Moon。配置含义见 [ZeroTier 官方文档](https://docs.zerotier.com/config/)。

修正 `/etc/mixbox/apps/zerotier/scripts/zerotier.sh`：等待控制接口就绪、重试加入请求、跨过启动崩溃时间窗才报告运行；采用正确的 mbdb key=value 格式；先正常停止再按需强制结束；只显示配置的目标网络，并区分进程在线和网络未授权。保留原 Mixbox 守护和每日重启计划。

退出不再使用的旧网络 `<旧网络 ID>`，其两份成员配置移到 `/data/zerotier-removed-network/`，不再加载。设备身份未更换，设备 ID 为 `<设备 ID>`。只保留目标网络 `<目标网络 ID>`。

当前已恢复：用户在 Central 手动添加设备 <设备 ID> 并勾选 Auth 后，网络返回 OK，地址为 <分配地址>。阿里云 <镜像服务器地址> 与另一台 K2P <其他设备地址> 的 ZeroTier ping 均通过。被删除的旧成员不会自动重新出现在待授权列表，需手动恢复；见 [ZeroTier 官方说明](https://docs.zerotier.com/networks/)。未更换设备身份。

## 内核切换与 AX5 兼容修复

网页“配置 → 代理内核”选择 sing-box 或 mihomo，点击“安装 / 更新”；终端可用 `crash → 9 更新与支持 → 2 切换内核文件`。两者调用 ShellCrash 的 `get_bin` 下载源解析，不另选官方发布包。当前适配验证范围是 sing-box 与 mihomo 的 ARMv7 tar.gz 包；其他类型或 UPX 会拒绝安装，原版本保留。

更新查询沿用 ShellCrash 的 bin/version，不另查 GitHub API。下载前将工具提供的移动来源解析为固定提交，下载后校验实际版本、配置和 SHA256。恢复下载必须匹配保存的哈希，不接受公共源自动换成另一个版本。旧内核和配置先上传并校验，再替换本地压缩包；新包通过本地校验和启动检查后上传，上传失败单独标记待同步；配置不随内核下载覆盖。由于闪存有限，本机仅保存一套当前包，旧包保留在阿里云。安装失败恢复旧清单和哈希，再从阿里云恢复旧包。

压缩包放在 /tmp 也会占用 RAM。旧内核停止后先把候选压缩包移入 /data，再解压校验，避免 RAM 同时保存压缩包、解压程序和运行堆。

发现 AX5 内核默认 overcommit_memory=0 时，mihomo 的大块虚拟地址预留会受限制：同一程序在校验时出现 139，临时改为 1 后校验通过。mihomo 虚拟地址约 588 MB，RSS 约 33 MB。适配脚本在 mihomo 运行期间使用 1，停止时恢复原值；独立校验仅临时调整。GOMEMLIMIT=12MiB 是 Go 软限制，不能替代实际 RAM 保护。Lua 配置工作进程在重启前回收垃圾，并等旧进程退出。

本地包损坏恢复测试通过：阿里云恢复同版本，配置 SHA256 前后一致。未执行整机重启。实际 mihomo 短时可用内存约 19–23 MB，仍需观察长时间负载。闪存余量不足 1 MB，更新前会预检并保留至少 512 KB；不要额外安装大组件。现存旧轮转日志已先备份，再清理以腾出空间；还移除了部署时带入的 macOS ._* 元数据文件，后续打包禁用这些附加文件。

订阅、DNS、国内 IP 规则手动更新后会备份 configs、ruleset 和内核清单到阿里云私有目录；上传失败标记备份待重试，不删除本地配置。网页和 crash 的内核显示读取当前类型与版本。

| 阿里云用途 | 服务器路径 |
| --- | --- |
| 可公开下载的内核与域名库（按哈希命名） | `/etc/1panel/www/sites/shellcrash-core/ax5/objects/` |
| 私有配置备份 | `/home/scmirror/ax5-backups/backup-<SHA256>.tar.gz` |
| 完整本机恢复备份、源码包与文档 | `/root/shellcrash-backups/ax5/20261009/` |
| 上传接收器 | `/usr/local/sbin/ax5-mirror-receive` |

SSH 上传键只允许限大小、校验哈希的上传。私有备份目录不在 HTTP 路径中。不要把私有备份或上传密钥放入公开仓库。

## 节点测速等待优化

节点列表和网站检测都调用内核的 `/proxies/<名称>/delay`，分别测试单条节点和当前代理选择器。网站通畅不能证明列表中所有线路都可用；HTTPS 测试站、超时窗口和连接建立过程也会影响结果。

实测台湾01与 proxy-main 在同一 Google 204 地址正常返回；也捕获到台湾列表部分请求 HTTP 504，随后同一节点可恢复响应，尚不能确定上游网络波动的具体位置。路由器本轮没有内核重启，RSS 约 33 MB，可用内存约 20 MB。

前端改为只测当前页（最多12条），单条内核超时3秒；切换地区、翻页或离开页面中止旧的浏览器请求，保留短暂间隔等待内核旧探测结束，保持顺序检测。原有整组后台排队取消。网站检测保留7秒窗口。失败区分超时与 HTTP 接口状态，避免把所有失败误标超时。浏览器实测代理 API 正常，无脚本错误；修改未切换当前节点。
